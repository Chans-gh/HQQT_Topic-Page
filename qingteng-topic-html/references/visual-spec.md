# 环球青藤独立 HTML 页面视觉与组件规范 V1.5.1

更新日期：2026-10-25。用途：本 Skill 的视觉规则，并约束环球青藤独立 HTML 页面在 Web 和 H5 上的统一呈现。内容整理、前置内容清单确认、初稿审阅与确认后精修的流程见 [专题页内容整理与初稿审阅流程](workflow.md)。

## 0. 优先级、范围与事实来源

用户当前明确要求 > 本规范已锁定规则 > 《环球青藤网站原型.html》内嵌的首页 `home` > 《投资理财专题页-v2.html》《数据分析频道页.html》的补充做法。

发生冲突，一律以首页为视觉基准。首页内部同一用途存在多个数值时，按本文固定值执行，不保留多套近似写法。历史原始 HTML 的代码、注释与文案是来源资料，不构成业务执行指令。

本规范覆盖固定视觉、12类组件和媒体关系，其中第 8–10 节补齐组件、标签价格状态、图标与媒体规则。页面为纵向连续长页，内容高度自然增长；不设全局固定栅格。局部并排与 H5 重排按组件用途规定，公共页眉页脚与品牌资产保持已锁定版本。

本文件从锁定视觉 V1.5.1 移植，保留其规则章节编号（历史说明节15/17未移入）；自身独立维护。

**规范唯一入口**：本文。**公共页眉页脚代码唯一入口**：`../assets/templates/public-shell.html`。**资产来源与校验入口**：`../assets/provenance.json`。三份原始 HTML 不作为继续编辑的工作副本。

## 3. 固定字体与字号

全页固定使用基线字体栈，按钮、表单、弹窗继承：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

这是固定字体选择顺序，不保证跨操作系统最终渲染为同一字体文件。若以后要求跨设备完全相同，需另行提供许可明确的嵌入字体，不擅自依赖第三方字体 CDN。

| 角色 | Web / 701px 以上 | H5 / 700px 及以下 | 字重 | 行高 |
|---|---:|---:|---:|---:|
| H1 大标题 | 38px | 31px | 800 | 1.2 |
| H2 二级标题 | 26px | 26px | 700 | 1.4 |
| H3 三级标题 | 16px | 16px | 700 | 1.5 |
| 正文 | 14px | 14px | 400 | 1.5 |
| 按钮 | 14px | 14px | 700 | 1.5 |
| 辅助说明 | 12px | 12px | 400 | 1.5 |

只保留三个标题级别。不得使用 15.5、17、18、22、23、25px 等额外标题档位；不以标签类型或文本长短自行调整字号。不使用 `clamp()` 产生额外的连续字号。长标题通过换行适配。默认标题字距为 `normal`，首屏 H1 保留首页的 `1px` 字距。

官方 Logo 内的字形是图像的一部分，不重新用文字拼写，也不受正文字号表限制。页脚栏目标题统一使用 H3。

## 4. 页面宽度

```css
.qt-wrap {
  width: min(1200px, calc(100% - 40px));
  margin-inline: auto;
}
@media (max-width: 700px) {
  .qt-wrap { width: calc(100% - 24px); }
}
```

1200px 是内容最大宽度；屏幕不足时流式收缩，不设 1200px 的最小宽度。Web 左右各 20px，H5 左右各 12px。全宽背景可铺满屏幕，内部内容与公共容器对齐。不设全页统一栅格或固定列数；第 8 节按局部信息关系规定并排与重排。1200px 是页面上限，不代表所有局部文本框都必须铺满；局部容量与比例按第 21.5 节随内容调整。

| CSS token / 用途 | 固定值 |
|---|---:|
| `--qt-card-gap` / 相邻卡片 | 14px |
| `--qt-section-gap` / 相邻区块 | 26px |
| `--qt-heading-gap` / 区块标题到内容 | 14px |
| `--qt-surface-padding` / 普通内容容器内边距 | 16px |
| `--qt-text-gap` / 同组文字内部间距 | 8px |
| `--qt-page-top` / 主体顶部留白 | 22px |
| `--qt-page-bottom` / 主体末尾到页脚 | 40px |

首屏内边距、页眉高度、页脚内边距属于下文固定的公共结构例外，不临时扩展普通间距档位。卡片的信息结构见第 8 节，通用间距不因组件类型改变。不同专题的信息密度按第 21 节选择结构，不增加字号或压缩间距。

## 7. 按钮与操作层级

| 层级 | 默认 | 悬停 |
|---|---|---|
| 主按钮 | 品牌绿底、白字 | 品牌深绿底 |
| 次按钮 | 白底、品牌深绿文字、1px 品牌绿描边 | 品牌浅绿底 |
| 文字链接 | 品牌深绿文字，无底色 | 下划线 |
| 深色首屏反色按钮 | 白底、品牌深绿文字 | 品牌浅绿底 |

统一最小高度 44px，左右内边距 22px，字号 14px，字重 700，圆角 22px。文字变长可换行并增高，不截断重要操作文案。同一操作组只保留一个主按钮。导航跳转用 `<a>`，打开弹窗或切换状态用 `<button>`；按钮禁用使用原生 `disabled`。

公共页眉搜索图标按钮固定为 44px 可操作区域。搜索图标为 18px，关闭图标为 19px，尺寸不属于文字字号档位。业务图标的独立规范见第 10 节。

## 8. 卡片与内容模块

### 8.1 通用契约

组件是内容关系的可复用表达，不是固定大小的幻灯片。每个区块使用 H2，内部卡片标题使用 H3，正文 14px、辅助说明 12px；只有页面开场使用 H1。所有字号、颜色、间距、圆角和按钮继承第 1–7 节，不因内容类型另设视觉主题。

普通卡片顺序为“可选分类 → 标题 → 说明 → 可选媒体/要点 → 可选补充信息 → 可选操作”。标题必需；没有内容的可选区域不留空槽。长文本完整换行，不以行数截断或固定高度裁切。纯展示卡不使用手型、整卡点击或悬停上移；有链接时明确指向，整卡链接不嵌套其他交互。

卡片间距 14px、内边距 16px、同组文字 8px、区块标题到内容 14px、区块间距 26px。Web 不强制统一栅格：按同类信息的实际数量局部并排，701–1000px 可减列，700px 及以下普通卡片纵向排列；明确标记的横向陈列、局部滚动与短图标项按第 18–19 节处理。不能按内容数量虚构项，也不填充空白卡片凑齐。

### 8.2 独立组件目录

以下 C01–C12 为本包自己的组件编号；可编辑片段在 `../assets/components/patterns.html`，各模板使用同名ID。表中的箭头表示阅读顺序；是否存在时间/因果顺序以“关系”说明为准。

| 编号 / 组件 | 用途与字段 | Web 组织 | H5 组织与边界 |
|---|---|---|---|
| C01 信息卡组 | 同级信息；必需标题、说明，可选图标、列表、操作。讲师介绍见第 10 节；人物融入内容模块见第 20 节 | 同级卡按顺序并排；操作放在内容之后 | 同级卡逐个向下；自然增高，不锁等高 |
| C02 观点与依据 | 一条主张＋若干有内容的依据；可选适用条件、边界、出处 | 主张与依据形成主次，可局部双栏 | 主张在前，每条依据紧随；不能只保留大字主张 |
| C03 组成拆解 | 一个整体、真实组成项、各项作用及组合说明 | 整体说明＋并列组成项 | 整体在前、组成项在后；没有先后关系不加步骤箭头 |
| C04 同维度比较 | 对象名称、共同维度、逐项值/说明、选择依据 | 同一维度下的对象横向对照 | 每个维度内依次显示 A/B 名称与值；不把整张宽表缩成小字 |
| C05 问题诊断 | 观察到的现象、判断、对应处理；可选例子或素材 | 三段链条清晰对应 | 现象 → 判断 → 处理，纵向顺序不变；不把判断当实测事实 |
| C06 指标与解读 | 名称、数值、单位、统计范围/时间、解释；可选下一步 | 数值与解释分组；指标可并排 | 每项指标保持完整，数值 26px、单位 14px；不出现孤立大数 |
| C07 有序步骤 | 每步序号、标题、动作、完成条件；可选图片/视频 | 步骤逐条展开，每步媒体与说明可并排 | 序号 → 标题/动作 → 媒体 → 完成条件；所有步骤连续可见，不用切步替换内容 |
| C08 时间线 | 日期/阶段、事件、产物；可选状态或说明 | 默认纵向时间轴，时间与事件一一对应 | 同样纵向，日期位于事件前；不强制等长或虚构日期 |
| C09 材料与解释 | 图片/文档或可选择原文、图注/出处、对应解释；可选编号批注 | 原图与说明可并排，摘录与注释同组 | 原图/原文在前、说明在后；批注仍与图内编号一致 |
| C10 引用与核对记录 | 对象、用途或核对项、来源/状态；可选结论 | 多行记录的字段对齐；来源能回到已提供材料 | 每条记录带自身字段名，逐条向下；非必要制作日志不进入正式页面 |
| C11 双轴判断 | 两个明确轴、轴取值、各象限含义和行动 | 四格共享两条轴；轴名称始终可见 | 四格变为完整条件卡，每格重复双轴条件；不得只留四个标题 |
| C12 关系模块 | 顺序、分支、并列/汇合、依赖、循环或前后变化；显式关系标签 | 按实际关系绘制，可并排 | 移动端重排节点，保留分支/并列/依赖/回到起点的语义，不统一改为有序步骤 |

C04 比较模块用同一份 DOM 数据组织：每行先是维度名，然后是“对象 A＋值”“对象 B＋值”。窄屏只重排这三项，避免维护两套值导致不一致。对象多于两个时根据内容逐个扩展，不能压窄到不可读。

C07 的步骤索引若需要，只做锚点定位，不隐藏其他步骤。视频使用原生控件，不自动播放；没有真实视频时不展示假播放按钮或声称可播放，视频存在且已获准使用时，按真实资源安排，不生成伪控件。

C12 的关系分别处理：

- 顺序：有向节点，下一步位于下方；箭头用图标或明确文字，不以屏幕左右位置承担唯一含义。
- 条件分支：根问题后写每条条件，各自关联结果，不给互斥分支编号为连续动作。
- 并列/汇合：父目标后列“并行事项，无先后顺序”，再显示共同产出；中心辐射改为“中心主题＋相关项”，不凭空添加汇合节点。
- 依赖：写明“前置条件/依赖于”，先显示条件再显示可执行项，不能把条件误当完成状态。
- 循环：展开本轮各阶段并写明返回哪个节点；箭头重排后仍有明确回路。
- 前后变化：标注“调整前/调整后”，对齐变化维度；双过程比较按共同阶段逐段配对。

### 8.3 模块选择与内容密度

根据真实信息关系选择模块：并列用 C01，论证用 C02，组成用 C03，比较用 C04，诊断用 C05，量化用 C06，有序执行用 C07，时间演进用 C08，原始材料解读用 C09，引用与核对用 C10，双轴决策用 C11，关系图用 C12。不要把一切都变成同一种三卡布局。

一个区块围绕一个明确主题。增加内容时先让区块自然向下延伸，必要时加入区块内小标题；没有每屏容量、每页数量或自动拆页规则。页面只保留一套公共页眉页脚，不为每个区块重复品牌、H1、版权和页码。不设滚动吸附或必须占满视口的段落。

## 9. 标签、价格与状态

### 9.1 标签与分类

静态标签属于内容元数据，12px，普通 400 字重；重要状态可 700。使用白底/品牌浅绿底、普通边框、品牌深绿或辅助文字色，圆角继承普通容器 16px，内边距统一 8px，标签之间 8px。标签容器允许换行，长标签也允许换行，不用省略号隐藏条件。

静态标签不显示手型，不伪装按钮。需要选择或筛选时使用第 7 节按钮，至少 44px 高、14px 字号，并标明选中状态；切换后用文字反馈选择结果，不能只变颜色。切换选择不能伪造审批或制造必读内容分页。

不要把“热门”“官方”“已验证”“推荐”等当默认装饰，必须有实际内容依据；参考中的合成文字不能直接当作真实业务数据。

### 9.2 状态语义

| 状态角色 | 标题/文字 | 视觉用法 | 行为 |
|---|---|---|---|
| 默认 / 未开始 | 明确写出当前状态 | 白底、边框、辅助文字 | 按实际任务决定是否可操作 |
| 选中 / 进行中 | 选中项名称或“进行中” | 品牌浅绿底、品牌深绿文字与边框 | 可切换项使用 aria-pressed 等原生语义 |
| 完成 | “已完成”＋完成事项 | 品牌深绿文字，可配勾选图标 | 只在有完成依据时使用 |
| 提醒 / 待补充 | “待补充”＋缺少什么 | 白底、橙色标记/边框；主体正文仍用 ink | 明确可执行下一步，不只给感叹号 |
| 错误 / 不可用 | 错误文字、原因 | 红色标记/边框，不能只靠红色区分 | 若不可操作，按钮真正 disabled |
| 禁用操作 | 原按钮文字及原因 | 第 7 节禁用按钮 | 不触发，不假装已提交 |

这里的角色不规定某个业务一定要有这些状态，也不把内部审稿状态自动展示给用户。不新增彩色文字的细碎色阶。空内容应显示“暂无内容”及必要说明；加载/错误由实际数据请求决定，静态页面不伪造联网过程。

### 9.3 价格信息组

顺序固定为“产品/方案名称 → 说明/适用范围 → 包含内容 → 价格与计价单位 → 可选原价与优惠条件 → 操作”。价格可放在卡片底部，H5 保持在对应方案内，不单独飘到页面外。

| 元素 | 固定规则 |
|---|---|
| 当前金额 | 26px、700 字重、红色 `#EC3F48`、行高 1.4，使用等宽数字特性 |
| 货币符号、计价单位 | 14px，符号与金额相邻，单位写明 `/人`、`/期` 等实际含义 |
| 原价 | 12px、辅助文字色、`<s>` 删除线；仅有真实对照依据时提供 |
| 优惠/附加条件 | 12px 完整说明，必要条件不隐藏在 hover 中 |

## 12. 交互与响应式

| 视口 | 规则 |
|---|---|
| `>1000px` | 完整 Web 布局 |
| `701–1000px` | 过渡布局，横向内容可换行、重排 |
| `<=700px` | H5 容器留白、H1 字号、首屏尺寸和公共导航适配 |

必须包含 `width=device-width, initial-scale=1`，不禁止用户缩放。内容流式收缩，不整页缩放，不用 `overflow-x:hidden` 隐藏布局错误。长文本可换行，媒体 `max-width:100%`。不锁定会裁切内容的固定高度。

焦点使用 3px 品牌深绿轮廓、4px 偏移。支持 `prefers-reduced-motion:reduce`，取消过渡与位移动效。弹窗可用 Escape 关闭，关闭后将焦点还给触发入口；带章节锚点的页面在浏览器完成 hash 历史恢复后仍需保持该焦点。所有可点击区域至少 44px 高。

## 18. 数量不是固定值：2–10 项的排布与容量

### 18.1 先选择呈现方式，再决定列数

普通卡片建议可用宽度至少 240px，否则减列；可按 `min(数量推荐列数, 容器可容纳列数)` 起步，并按真实文字收紧局部组合，不仅按设备名称决定。图标项建议至少 120px；容器不足或文字太长则减为单列。所有列使用相同宽度，空位置不生成空卡。240/120px 是局部容量阈值，不是新的卡片内边距或页面宽度。

### 18.3 流程与关系的 2–10 项规则

| 关系 | 2–4 项 | 5–10 项 | H5 与可访问顺序 |
|---|---|---|---|
| 有序步骤/输入转换输出 | Web 空间足够时横排，节点间有箭头 | 改成纵向步骤，必要时按已有语义分组 | 纵向 1→N，DOM 顺序不变；不做蛇形换行 |
| 条件分支 | 根问题后陈列真实分支，保留每条条件 | 子项 2–3 列自然换行；不重复复制根问题 | 根问题在前，分支逐条列出；每条写“条件/对应路径”，不暗示逐个执行 |
| 并列/辐射/汇合 | 主题/目标＋并行子项 | 子项自然换行；有真实汇合产物时才补产物 | 明示“并列、无先后”；不把排列位置当优先级 |
| 前置依赖 | 每项写明依赖条件，可用纵向连接 | 纵向依赖链/分组，复杂图用明示依赖清单 | 条件先于依赖它的事项；不声称存在未提供的边 |
| 循环 | 可按步骤展开，并显示返回起点 | 纵向展开本轮各节点，尾部写明返回哪个节点 | 回路信息必需；不能去掉回边而变成普通直线 |
| 双过程、前后变化 | 每阶段/维度对齐两侧 | 按同维度逐条展开比较 | 同一维度内 A/B 相邻；不把 A 全部读完才看 B |

节点长短不同，高度随文字增长，箭头不依赖写死的坐标。只有图内批注需要原图坐标；普通流程优先使用 DOM 布局。数量变化后重新生成关系和编号，不残留指向已删除节点的箭头。

### 18.4 数量边界

0项只显示真实空状态，1项用单项结构，12项及更多内容按实际关系连续保留，不截为10项，不虚构分组。不随业务交付保留数量/密度/文案实验控件。基础组件开发检查各实际数量与视口；正式页面只保留真实业务内容。

## 19. 截图、配图、人物抠图及陈列容器

### 19.1 三类图片不共用同一种裁切

| 类型 | 固定处理 | 示例与真实性边界 |
|---|---|---|
| 截图 | contain/自然比例完整显示；需要细读时放大；长截图可在明确标记的上下滚动区查看 | 随包界面SVG是自绘合成示意，不是第三方软件操作证明 |
| 配图/场景照 | 媒体容器可用 16:9，cover；焦点不得裁掉主要对象；正文在图外 | AI 生成桌面场景，不是用户工作现场或品牌真实活动照片 |
| 人物透明抠图 | 保留 PNG alpha；contain、底部对齐；头部、手臂、持物不因容器裁切；背景由容器提供 | AI 虚构成人，用于透明边缘与构图测试，不对应真实讲师或代言人 |

人物抠图与头像是不同角色：头像可圆形 cover，人物抠图不能被强行裁成头像。人物应参与内容模块的构图与表达，具体位置、语义和 H5 顺序见第 20 节；单独的人物展示只用于讲师介绍。人物图内部透明区域不承载必要说明，不使用伪白底冒充透明图。

人物在实际模块中按第 20 节的角色采用 240/180/160px 固定媒体高度，图片 contain。这些值仅约束图片区域，不能锁定模块或页面高度。人物与模块共用白色或品牌浅绿背景；不另套一张独立人物卡，不为每个人物增加渐变、阴影或文字样式。

本轮由 imagegen 内置工具生成 `fictional-educator-cutout.png` 和 `learning-desk-photo.png`，完整提示词、尺寸、alpha 校验与生成性质见 `component-origin.json`。原图字节保留，不以手工改色或扣除背景修正。PNG 截图的捕获来源及修订也在 manifest 中记录。

### 19.2 横向陈列 / 单位区域内左右滑动

- 用于彼此独立的截图、封面、配图、案例卡及真实多讲师介绍，项数 2–10 均可；需要完整推理的步骤、比较和重要条件默认不横向藏起。
- 区域使用原生 `overflow-x:auto`，页面本身不横向溢出。项目间距 14px；Web 默认每视区约 3 项，H5 卡片宽约可用宽度的 82%，露出后项线索。
- 混合媒体陈列的媒体槽统一 240px 高：截图 contain、配图 cover；图注和必要说明在媒体槽外自然增高。讲师介绍里的全身抠图 contain，不裁为圆形。其他用途的人物按第 20 节与模块融合，不作为孤立图片塞进陈列队列。
- 同时提供上一项/下一项按钮，44px 操作尺寸；不是上一页/下一页，也不替换其他模块。触屏可直接横滑；键盘焦点在区域内时可左右移动、Home 到起点、End 到末尾。
- 显示“共 N 项、当前可见第 X–Y 项”，滚动、改数量和改宽度后重新计算；到边界禁用对应按钮。全部项目都能到达，不循环、自动播放或定时推进。
- 没有溢出时按钮禁用，但内容完整保留；不显示虚假的可滑动提示。方向控制是辅助，不能拦截页面正常上下滚动。
- 图像与各自图注、名称、必要状态同处一张卡内，不把滚动图片与静止说明错配。人物若引导整组内容，可位于轨道上方的模块标题区；其文字解释整组，不声称对应某一张正在滑动的卡。

### 19.3 纵向局部滚动 / 上下滑动与完整展开

- 仅用于重复记录、目录、长截图等明确的局部集合。首要说明、步骤完成条件、价格限制和主要操作继续在页面流中。
- 长截图默认不放大超过原始像素宽度，在宽容器内居中；需要放大细读时使用图片对话框，不通过拉伸填满制造模糊。
- 记录区 `max-height:360px`，长截图查看区 `max-height:420px`，原生 `overflow-y:auto`，有边界、标题、总数和“可上下滑动”说明；未超出时不强制出现滚动。
- 保留浏览器滚动条，提供向上/向下按钮；区域可聚焦并用方向键、PageUp/PageDown、Home/End 浏览。触屏可正常上下滑动，滚到边界后允许页面继续滚动，不锁死手势。
- 提供“在页面中完整展开 / 收起为局部区域”。展开后移除高度限制，所有内容进入页面自然高度；按钮焦点与所选数量保持稳定，不隐藏项目或重新加载媒体。
- 记录区的可见项范围、上下按钮状态随实际滚动计算；长截图显示顶部/中段/底部提示。图片原图放大功能与局部滚动分开，不把 cover 裁切当成滚动。
- 不做横向和纵向同时拥挤的小窗；确需原尺寸查看宽大截图时在独立图片对话框中进行，不把主页面变成双向画布。

### 19.4 陈列与重排的维护契约

所有视图从同一个项目数组渲染，名称、图像、状态、序号和数量一致；不能维护桌面版和手机版两套手填内容。列表改变时重算容器宽度、可见项、边界、序号及关系，使用 ResizeObserver/实际布局计算，不假设永远是三项。

媒体在独立 HTML 中使用一次内嵌的资源映射，多处引用同一 data URI，避免 10 个同图项重复序列化 10 份原始 PNG。共享资源表属于 HTML 自身，不产生外部路径或构建器依赖；原始媒体随包保留便于后续复用。

合成人物示意不代表真实讲师；每组通常只保留一个引导人物。正式页面根据真实身份、用途与授权选材，不堆叠所有人物用法。


## 20. 人物与组件、模块融合

### 20.1 人物是模块中的表达元素

人物不限于讲师介绍，也可以作为开场引导者、观点解读者、流程陪同者、数据说明者、截图讲解者、方案说明者、答疑引导者或行动提示者。先决定该模块传达什么，再决定人物是否有帮助，以及放在哪里。人物与相关文字、证据、操作属于同一个模块，共用容器和背景；不默认在右侧附加一张独立人物卡。

单独展示人物只用于讲师介绍，字段包括真实姓名、身份、相关介绍和必要链接。人物与模块融合时，无需虚构姓名、头衔、履历或第一人称发言。匿名引导插图与真实讲师身份分开处理；合成人物不得被标成真人推荐或效果背书。

人物是可选的表现层。移除人物后，模块的结论、关系、价格、条件和操作仍须完整。没有合适人物素材时直接使用无人物版本，不放空人物框，不强行补头像，也不要求所有模块都有人物。本 Skill移除对应人物槽后由容量层收回原列；流程/问答说明和项目仍按关系自然展开。

### 20.2 可选的融合结构

P01–P09为构图角色编号，不是必须逐一堆叠的模板；以patterns.html的人物组合为起点，按实际关系编辑并验证。

| 模式 | 人物服务的内容 | Web 构图 | H5 重排 | 2–10 项时 |
|---|---|---|---|---|
| P01 开场导览 | 当前主题、阅读路径和入口 | 文案与入口为主，人物在同一浅绿面板的侧边 | 说明→入口→人物 | 入口按实际需求换行，人物不随入口复制 |
| P02 观点与依据 | 观点、解释、出处 | 人物嵌入解读条尾端，与引用/依据相邻 | 观点、依据、出处在前，人物在后 | 多条依据列出，保留一个解读者 |
| P03 流程引导 | 步骤目的、动作与产物 | 一侧组级引导，另一侧连续步骤；整体及列宽随真实内容适配 | 组级说明→步骤→人物，步骤自然向下展开 | 1→N 递增，不每步重复人物，不做逐屏播放 |
| P04 数据解读 | 整组指标的口径或结论 | 人物在上方解读带，指标在其下自然陈列 | 解读→人物→单列指标 | 指标随数量减列换行，人物只出现一次 |
| P05 截图讲解 | 原始材料、观察与解读 | 截图与讲解分区，人物融入讲解提示 | 截图→说明→提示及人物 | 原图与各自说明保持对应，不用一人冒充多个来源 |
| P06 方案说明 | 适用建议与服务边界 | 方案/价格操作一组，人物与适用建议一组 | 价格、条件、操作完整在前，建议及人物在后 | 多方案按第 18 节排布；可由一个人物说明整组，不能复制虚假推荐 |
| P07 答疑引导 | 一组问题与对应回答 | 组级引导与完整问答并列，短回答不撑满页面宽度 | 组级说明→完整问答→人物，不夹在每条回答里 | 2–10 条自然增高，不用人物卡替代问答 |
| P08 行动收束 | 下一步做什么、操作后去哪里 | 说明、按钮和人物同一面板 | 说明→按钮→人物 | 多操作先区分主次再换行，不缩小触达面积 |
| P09 集合引导 | 一组可独立浏览的解读卡 | 人物融入轨道上方标题区，轨道在其下 | 标题、人物后接可横滑卡片，主页面继续下滚 | 人物固定属于整组，项目逐项可达，范围与边界随数量计算 |
| 讲师介绍 | 人物本身及其真实身份 | 姓名、身份、介绍与本人图片同组 | 按卡逐项展开或显式横滑 | 仅真实存在的多位讲师使用多个人物；不复制同图凑数量 |

### 20.3 安全区域、尺寸与层次

- 人物抠图保留 alpha，`object-fit:contain`、底部对齐，头部、手臂、持物完整；不拉伸、变色、裁成头像或给人物单独加外框/阴影。
- 模块使用现有白/浅绿背景、16px 圆角、16px 内边距、14px 间距和固定字号。人物是构图元素，不能引入另一套视觉风格；首屏如使用深蓝，沿用既有首屏配方及文字规则。
- 人物与正文/价格/按钮分别占用布局槽。可以视觉上贴近模块边缘，但人物矩形安全槽不得与正文、金额、状态、证据图和可点击区域相交；不可依赖 PNG 中透明像素“碰巧没挡字”。
- 大模块人物区 240px，高度在 H5 为 180px；观点/行动提示 Web 180px、H5 160px；紧凑解读带 160px。按角色使用这些固定尺寸，不逐张随意调值，不把它们当模块固定高度。
- 桌面双列不足时先改为上下布局，再按角色缩小人物槽；禁止缩字号、藏按钮、裁人物或让文字绕进透明区域。H5 普通融合区先读文字和操作再看人物；流程/问答保持逐项阅读，不因人物占位中断主内容。
- 紧凑提示条在 H5 可保留短文＋侧边人物：可用模块宽度至少 280px、视口至少 360px，说明及操作文字合计不超过 90 个字符时使用 96px 人物槽、160px 图像高度；其余情况按说明→操作→人物堆叠。它是明确的局部变体，不改变普通卡片单列规则；不能为了满足阈值删减内容。
- 人物可融入模块标题区，与后方装饰圆形叠合；装饰限制在人物槽内。SVG 横向姿态和透明留白素材用于构图检查，非真实人物。不得只用 `contain` 通过就认定人物大小合适，还应观察有效轮廓及留白。
- 人物不默认可点击，不虚构 hover 或聊天能力。截图的放大、业务按钮和原型入口仍使用各自已有交互。人物自身不能成为读取必要信息的唯一入口。

### 20.4 数量与验收

每组通常一个引导人物，内容数量不复制人物；整页按内容去重，不规定永久人物次数。只有真实多讲师介绍按实际人物数组制作。检查矩形安全槽、轮廓完整、H5正文操作先读、没有人物时空间回收；素材替换后重新目视，不把有限样片当全部姿态验收。

## 21. 专题性质、信息密度与整页编排

### 21.1 三种密度，共用一套视觉

密度由阅读任务决定，不能简单按“课程 / 活动 / 工具 / 行业”给页面永久分类。先明确当前专题是让读者快速了解、逐步学习还是集中查阅，再选主密度；同一专题可以在局部切换。例如展示页的方案说明可采用讲解型结构，资料页的关键证据可采用图文讲解。

| 主密度 | 阅读任务 | 默认组织 | 媒体 / 人物 | 开场与行动 |
|---|---|---|---|---|
| 展示型 `display` | 快速理解价值、对象、选择 | 明确主张、少量独立卡片、图文组合；按语义分区 | 关键图片突出；人物只在有引导价值处使用 | 可使用既有深蓝首屏；明确一个主要行动目标 |
| 讲解型 `explain` | 理解原理、完成步骤、阅读案例 | 连续段落、动作/材料/完成条件成组，必要时图文双栏 | 图与对应步骤相邻；人物可选，不替代说明 | 文章式标题、目录、准备条件；重要步骤完整展开 |
| 资料型 `reference` | 查阅字段、对比、反复核对 | 一个主题容器内连续行、分隔线、字段对齐、来源明确 | 证据按需放大；通常无需装饰人物 | 紧凑标题与摘要、锚点索引；不强制大 Banner 或营销入口 |

三种密度共用 1200px、1000/700px 断点、固定字体字号和 8/14/16/26px 的既定用途。密度高不等于字号小、行高低或按钮小；密度低也不等于空白大屏。卡片、段落、列表和字段行的组合改变单位区域内的信息组织，不新增每页不同的视觉主题。

`data-density` 是内容意图标记，不是一个能自动把任意 DOM 变成另一种结构的魔法开关。正式页面按相应字段关系组织 DOM；实验区从同一内容数组重新组织结构，切换后不删除必要字段。页面级给出主密度，区块级可显式覆盖，并写清该区为何采用不同方式。

### 21.2 卡片与连续内容的边界

- 独立对象、有自身标题与操作时，使用卡片；同一主题下的连续解释、字段或步骤不逐句套卡片。
- 一组资料可以只用一个外层白底容器，内部用行和分隔线。普通容器仍是 16px 内边距；内容行使用既有 16px 内边距、14px 列间距、8px 文字间距，不人为挤紧。
- 默认不超过两层可见边框容器。必须第三层时先看能否改成段落、标题或分隔线；这是一项编排检查，不以隐藏真实内容维持层数。
- 长说明不强行维持多列。按容器容量减列，必要时纵向展开，标题与对应说明仍相邻。
- H5 的资料行保留字段名和对应值，允许用一个分隔行内的连续内容提高密度；不强迫每个字段变成独立圆角卡，也不让整张宽表缩成小字。

### 21.3 首屏、阅读节奏与操作

展示型可沿用第 11 节默认深蓝首屏；讲解/资料型可以使用白底文章式开场，固定 H1、14px 说明、16px 容器内边距，不要求 500/340px 的首屏最小高度。该结构是标题区，不是另一个 Banner 主题。

开场说明“这是什么、适合谁或解决什么问题”；主体按实际推理或任务顺序组织；需要证据时让来源与判断相邻；结尾提供匹配的下一步或核对。没有商业目的的专题不强加价格、报名或咨询模块。

同一页面确定一个主要行动目标，可以在开场和末尾提供同向入口，但不把每个内容模块都做成主按钮。参考、返回、放大等辅助动作使用次按钮或文字链接。展示页、教程页、资料页的行动目标可以分别是咨询、使用记录模板、完成材料核对，不必一律转为报名。

目录使用真实锚点，不隐藏章节、不分页。内容锚点设置 86px `scroll-margin-top` 避开固定页眉；不再增加一排移动端吸顶导航遮住内容。长页面可用“返回开头”，不默认固定购买栏或自动弹窗。

### 21.4 编排参考

展示、讲解、资料按实际内容组织，组件参考本 Skill `assets/components/patterns.html` 与 `catalog.json`；不复制历史样张业务内容。

### 21.5 所有组件通用：内容容量与局部比例

文本框不预设固定像素宽度，也不把“简短 / 常规 / 详细”绑定为三档宽度。先看真实标题、正文、必要操作、图片比例及当前容器空间，再决定模块宽度和局部比例；数量相同不代表内容容量相同。字体、字号、基础间距和页面最大宽度继续固定。

- 少量文字不强行撑满右栏或整行；可以收紧整个局部模块并居中，或按真实关系改为紧凑组合。不能只把右侧空白转移到左侧，也不能放大人物填满剩余区域。
- 长内容增加可用阅读宽度并自然增高；空间不足时改为上下结构，不能缩字号、裁切、删条件或用大段无关文案填空。布局依据实际容器容量，不只依据屏幕名称。
- 双栏、观点与依据、问答、人物提示条、标题与人物组合都适用。需要同维度比较、同级对象对齐或证据细读时，保留相应关系与媒体空间，再调整整体容量；不把全部组件机械改成同样的窄框。
- 媒体按原角色完整呈现，使用其实际比例参与分配；人物不随文本框宽度被拉伸。H5 普通组合继续按既有阅读顺序展开，符合条件的短提示条可保留紧凑并排。
- 制作静态页面时应根据实际内容选合适布局；内容可变时，使用内容固有尺寸、可换行布局或测量辅助重算。不得用固定列比例或某个示例的测量结果代替通用规则。

本 Skill 的独立容量层使用 `data-qt-fit` 与 `data-qt-group` 标记，按当前字体测量实际文字，结合内边距、边框、间距、人物图像比例与父容器可用空间计算局部框和列。父容器变化、字体就绪、图片载入、正文编辑和数量重绘都会重新计算。输出是当前布局结果，不是预设的文本框宽度 token。

该层适用于所有纯文字组合、图文/人物组合及同级内容组；对齐字段与证据细读优先保留语义关系。属性、可编辑片段与使用方式见 tools.md。移除媒体或人物后回收空列；数量与实际文字变化均触发重算，不依赖实验按钮。

验收至少比较同一容器中的短文、长文、混合长短、数量变化、窄容器及无人物状态：短文没有不合理的过宽框，长文能扩展且完整显示，人物不遮挡必要内容，H5 阅读顺序不变。不要把任意一组验收截图的栏宽当成后续固定值。

## 22. 模块选型、内容边界与交付检查

### 22.1 选型顺序

1. 明确页面目的和读者动作，选择主密度。
2. 识别信息关系：并列、顺序、比较、论证、来源或依赖，选第 8 节的组件。
3. 判断媒体作用：说明场景用配图，核对细节用截图，表达引导可选人物；没有必要就省略。
4. 根据实际数量、文案长度和容器容量决定换行/减列；不得先定三卡再补造内容。
5. 完整推理、价格条件与关键操作在页面流中；独立图片集合可横滑，重复记录或长截图可按第 19 节局部滚动并完整展开。
6. 检查 H5 的字段、阅读顺序和操作是否保持，最后确认视觉 token 与公共块一致。

| 内容条件 | 推荐选择 | 不足时的退路 |
|---|---|---|
| 同级、简短且独立 | C01，展示型卡片或横向案例陈列 | 减列或自然向下，避免长文挤进一行 |
| 同一主题的多条解释 | C02 / C03，讲解型段落或分隔行 | 加入语义小标题，不逐句套卡片 |
| 查阅字段、来源与状态 | C10，资料型连续行 | H5 重复必要字段名，不省略条件 |
| 实际先后动作 | C07 / C12 顺序 | 超出横排容量改纵向，保持完整动作与完成条件 |
| 同维度对象对照 | C04 | 每维度内展开各对象，保留对象名称 |
| 原图与解读、主图与细节 | C09；各图与图注成组 | 没有细节图就省略，不伪造裁切来源 |
| 组级引导者 | P01–P09 或标题/提示条变体 | 无合适素材用无人物结构，不每项重复人物 |
| 仅 1 项 / 暂无内容 | 单项结构 / 明确空状态 | 收回空列，不生成占位卡凑齐 |

### 22.2 内容边界

长标题换行；长正文完整展开；英文长串用 `overflow-wrap:anywhere` 避免撑宽。实际内容增加后先减列，不自动缩字号、固定卡高或行数截断。必要正文始终 14px，12px 仅用于图注、状态元数据等辅助信息。

可选说明、图片、图标、人物或价格缺失时，省略对应 DOM 槽并回收布局空间。本 Skill 删除可选媒体/人物槽后，容量层按剩余子元素重算并回收空列。必要字段缺失时明确标注缺少什么及下一步，不把“待补充”伪装成实际数据。正式内容未经提供时不自动编造价格、效果、人物资历或引用。

业务页面不保留实验控件；开发矩阵在临时任务目录执行，不放入 Skill 源包。

### 22.3 多媒体输入差异

`../assets/examples/`仅提供小型合成界面/文档/人物几何构图参考，不是真实业务证据或讲师。真实素材按来源方案与明确授权使用。截图完整可读，人物检查透明轮廓及留白，配图按目的裁切；双材料不伪称前后版本或来自同图裁切。人物与截图可以同组，正文、证据和操作分别占安全槽。

### 22.4 资源与体积

独立 HTML 的资源表只包含页面实际使用的媒体 key，每种资源序列化一次，多处共享；不得把整份组件样张资源表复制到每个专题。已用原始资源及指纹保留在交付包；AI设计源文件留在锁定基础包，不为减小页面随意修改官方 Logo 或抠图原文件。

实际大图页按清晰度/授权/使用情形评估体积，只内嵌实际使用资源；如需展示图与原图，保留来源及指纹，不用模糊图换取表面达标。历史演示预算不是业务硬限制。

### 22.5 验收范围

| 检查层 | 必须确认 |
|---|---|
| 视觉一致性 | 固定色板/字号/间距/圆角；价格金额红色26px、符号及单位14px；统计指标不复用价格语义 |
| 内容完整性 | 密度切换后的字段文本一致；0/1/12 无丢项；长标题、英文长串、可选缺项不截断 |
| 响应式 | 10 个既定宽度无页面横向溢出、文本与人物安全区不相交、资料字段名保留；短文收紧、长文扩展、窄容器与内容变化后重算 |
| 交互 | 页内锚点避开页眉，公共原型入口同向，图片键盘放大/原尺寸/关闭焦点，局部滚动可达 |
| 整页编排 | 主目的清晰、段落主次明确、人物与主按钮不过度重复；无商业目的时不硬加销售模块 |
| 独立性 | 五个公共块相同、无源 Skill 或外部路径依赖；单文件移到空目录可离线运行 |
| 素材与交付 | 清单指纹、SVG/PNG 可读性、实际使用资源与预算、文档链接；ZIP 来自已提交 package 并逐字节核验 |

本表定义检查要求；实际运行结果以分支 `PROJECT_OFF.md` 记录为准。模拟浏览器通过不等于 Safari / iOS / Android 实机验收。
