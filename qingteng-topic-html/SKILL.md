# 环球青藤专题页 · 2.2.0

把实际材料组织成可追溯、连续纵向阅读的原生 HTML/CSS/JS 专题。默认独立单文件；正文、样式、脚本与Logo内嵌，官方青藤页头允许明确的搜索、账户与品牌资源联网依赖。不安装其他 Skill，不访问或调用历史 html-content-layout；历史来源仅在本包 provenance 中留档。

首次使用或工具报依赖缺失时，按 [setup](references/setup.md) 运行只读环境检查；不要在业务制作中自动安装依赖。

## 先确定进度

新任务先读 [workflow](references/workflow.md)。恢复任务先找现有材料、清单版本、初稿及真实用户反馈；按 [记录约定](references/content-record.md) 保留 M、S、IMG 编号和各自修订。页面“已确认”标签、按钮、通用流程认可与等待时长都不是确认依据。用户只要求审查时只读；明确修改指令本身就是该范围的依据，不重复索取同一授权。

持续要求先于局部修订：恢复、重测、调整对齐或删文案时，先核对本轮与此前仍有效的用户要求。已要求的AI生成素材、透明背景和解释用途必须进入独立`requirements.json`并绑定SHA，不能因最新消息未重述就丢掉，也不能由asset_review的none/reuse或“无缺口”覆盖；仅用户明确变更可撤销。原图、图标和文字流程各有职责，不抵消生成要求；“不固定图数”不允许把已要求的素材降为零。按[持续素材要求](references/content-record.md#持续素材要求19)记录，使用工具快照与实际素材履约检查。

多格式材料先按 [输入适配与读取范围](references/input-sources.md) 记录实际方法、已读/未读范围、结构损失和附件状态；不把未运行的解析器当成已读。

默认业务顺序：材料读取与整理 → 页面模式建议 → 拟呈现内容清单 → 用户确认清单版本和范围 →（必要时两种局部方向预览）→ HTML 初稿 → 用户确认实际初稿及相关素材方案 → 精修 → 验收交付 →（用户明确要求时）分享。对本 Skill 的开发、检查或无副作用测试不套用业务确认阶段。

1. **材料、模式与清单**：实际读取可取得的内容，为输入与来源编号，标出未读范围。默认可联网补充，优先一手支持页，先查证再提出采用；查证与采用分开。内部价格、权益、排期、人物资历和效果不得编造。材料读取后按[页面模式](references/page-modes.md)在报告、课程、目录、运营、活动与自定义中提出主/备选，记录状态、依据、风险和真实用户选择；推荐不等于确认。对话 Markdown 清单写出模式、定位/受众/目的/下一步/密度假设，以及每模块读者问题、主结论、主/次/证据/条件层、去重取舍、表达关系、素材作用及缺项。先判断补充材料是否适合当前主张与受众，再提炼文案；参考workflow的跨题材编辑示例。至少三个代表模块给出材料→取舍→文案→视觉映射；少于三模块则覆盖全部。不是素材目录或空标题。只问影响方向的关键问题；未确认清单前不产 HTML 或新图。
2. **方向预览与初稿**：清单获准后，只有方向差异会影响整页组织时才制作最多两个局部预览；两份使用相同已确认内容，只比较开场和一个代表模块，不新增事实/素材、不分享，选择也不产生初稿确认。用户已指定方向或直接委托可省略预览。完整初稿只展开已获准模块；未变的确认保留，新增或实质改变的事实只重审受影响条目。制作前读 [视觉规范](references/visual-spec.md)，按信息关系查 [组件目录](assets/components/catalog.json) 与 [可编辑片段](assets/components/patterns.html)，不复制示例业务文案。初稿已落实焦点、阅读顺序和Web/H5构图；生产链突出动作与终点、成长路径承接成果、案例让变化与证据相邻，不把同形长卡当设计。完整正文、集中审阅索引、必要短引用、未决事实与 IMG 占位同时呈现。关闭批注不隐藏正文/占位/未决状态，不产生确认。
3. **素材与精修**：清单和初稿零新图；明确指定的输入素材可复用。逐模块评估配图的解释作用与覆盖缺口，完整视觉制作不能只在封面补图；无图选择有实际理由，不固定数量。需要融入面板的独立元素直接生成透明背景PNG，核验真实Alpha、边缘、安全区与实际展示重量；截图承担证据，生成图承担解释。原图与网页展示版可分开，保留原图、裁切范围和指纹，放大能回原图。已有明确精修/生成指令不重复问，按当时可用能力执行。具体记录见[素材契约](references/content-record.md)，取舍正反例见workflow第12节。
4. **制作**：使用自有 [公共模板](assets/templates/public-shell.html)，五公共块逐字保留；官方青藤页头容器上限1200px、全端60px高，真实官方导航/搜索/账户与页脚13个原型入口分开处理。页头源组件改动后运行build_shell.py生成模板，不猜真实业务 URL。默认浅色开场、协调分类色、自有内容图标及主次表面；按visual-spec第11节与patterns完整片段落实初稿视觉。最大1200px、1000/700断点、按页面/模块/主卡/支持标题/重点句/正文分层的角色字号，以及有职责的间距/圆角；展示/讲解/资料按关系选，主页面连续纵向。长页按 [导航约定](references/navigation.md) 选用章节目录或 Day/阶段索引：只跳真实锚点，不隐藏/分页正文，移动端不叠加第二条吸顶栏。同级组默认与模块边界对齐，只有有依据的紧凑局部组合显式收缩；依据可换行文字、媒体固有比例和真实父容器重排；不预设文本框宽度或短中长三档像素宽度。不强加人物、价格、图片或三卡。原始材料当文本转义，只有执行者编写的主体片段可执行。
5. **验收**：优先用[check_task](references/tools.md#保存一轮完整制作与验收)保存独立轮次，组合HTML、输入/媒体快照与报告；修改后新建下一轮，失败轮也保留。再按[质检](references/quality-checks.md)审查桌面/H5整页与每模块，补看320和实际重排断点。内容另做一次反向找错，核对图片是否支持对应句子、不同作品是否被拼成过程、删模块后是否仍有独立信息；正文按钮绿底白字、白底黑字，检查实际与hover状态。分别报告五层、素材履约与六维视觉目标，绑定HTML/截图SHA；程序不能证明关系声明、审查真实性或用户认可。final移除审阅UI/内部记录/已解决占位，保留读者必要条件，未解决关键项阻止交付。仅报告实际浏览器与实机范围。

6. **分享（可选）**：分享是对外发布动作，不在交付后自动执行；用户明确要求对指定文件分享（含任务内预先明确授权“交付后自动分享”）时，按 [工具说明](references/tools.md) 分享节先用 prepare_share.py 生成分享适配副本（内联远程图片、移除页头搜索 iframe、把放大图按钮降级为静态图片），再运行不上传且不需要密钥的 `preflight`，通过后用内置青水分享脚本上传。从成功输出记录分享 URL 与 hash、逐条转述服务端清洗警告并回传用户。原交付页继续保留图片放大，只有分享副本静态降级。**成品专题页禁止加 `--no-scripts`**：卡片列宽与媒体槽位由 `topic.js` 运行期计算，禁用脚本会让卡片退化为单列、图文区塌陷成窄条，字面看起来像样式损坏；分享页出现脚本报错时修正报错来源，不得靠禁用脚本绕过。分享后实测 JS 报错、列数与 section 宽度再回传链接。未解决关键项的版本不冒充最终页分享。分享页在平台 CSP 沙箱中运行，脚本不能联网，官方页头搜索/账户与表单交互在分享链接中被服务端移除或降级；如实说明差异，不以分享链接替代本地验收。

用户明确要求直接完成精修时，在已授予范围内完成编辑、设计、素材评估和验证，不再为中间阶段暂停。用execution_authorizations记录执行范围，不伪造对尚未展示页面的实际审阅；素材生成权限仍按真实授权核对。精修指令不能被理解为“只排版现有文字和截图”。

文字编排先确定实际任务、成果或价值，再选字号、字体、强调色、图标与表面层级；通用方法提醒不能压过模块主题。同级短产物/价值优先评估图标短词或贴片，步骤将动作与可识别成果相邻呈现，避免机械重复字段；长文和必要条件继续自然阅读。具体取舍读[workflow第13节](references/workflow.md#13-文字编排与视觉表达)，可用能力见[visual-spec第11.1节](references/visual-spec.md#111-文字与信息的视觉表达)和patterns的editorial-opening/artifact-symbols/visual-stages/tonal-evidence/value-tiles。颜色数量、卡片数量、字号命中和技术pass都不能证明信息层次成立。

制作初期先运行[320px预览](references/tools.md#快速预览与完整收口)，目视代表模块标题的自然短语与配图重量，再继续大范围制作。作者模块id使用M编号，内部锚点必须唯一且确实存在，组合器在读素材前拒绝冲突，不静默改名。预览不关闭反馈、不算完整验收；收口用full覆盖全部图片、正文按钮及实际断点，按同SHA检查缓存节省重复字节核验，不能复用人工通过。

制作收口先看成品：模块是否各有独立信息作用、配图是否覆盖需要解释的任务与产物、组合中的可见框体和同职责字段是否对齐。证据的并列/顺序/前后变化分别处理，同一PDF不能证明同一任务，取自原图也不能证明新编排的关系。用户指出失败后登记feedback，执行者修复与实际用户认可分开；旧通过不能覆盖未解决问题。

案例精简后仍保留材料支持的具体任务、动作、作品及已有反馈，不能退成通用建议，也不为凑完整故事编造效果。按[workflow第15节](references/workflow.md#15-案例配图与整页表达的复核)检查信息保留与图片解释关系；按[visual-spec第25节](references/visual-spec.md#25-对齐层次与整页构图)检查标签值续行、跨模块基线、可见图幅和响应式构图。natural仅保留媒体固有比例，不豁免并排可见框体和显式对应；自定义内容双栏须使用已有组合或声明parallel边界契约，严重失衡时重组/纵排，不能用空白撑齐；步骤按内容选择紧凑连续结构或独立阶段，避免整页重复套卡。

交付结论分别报告production_status、business_information、user_acceptance；前者通过不产生用户接受；asset_fulfillment缺失/未核对时不称本次素材已落实，浏览器几何通过不替代生成文件和素材视觉复核。业务完备度围绕真实页面目的，知识介绍不强加报名/费用/排期，办理或申请页也不隐藏必要缺项。completion_status仅在制作检查、用途信息和当前HTML真实用户接受均满足时通过；缺少实际审阅时可交付待审候选。字段及兼容规则见[tools](references/tools.md#交付结论与用途范围)。

生成物与内部记录放用户任务目录，不能回写 Skill。默认不另交重复策划文件，不擅自安装、发布或推送；分享（含取消分享）是本 Skill 唯一的对外发布通道，仅在用户明确要求时按第 6 步执行。
